# 銀行收款對帳（第一版）

第一版使用國泰企業網銀匯出的 CSV，不會自動登入網銀，也不會保存網銀帳密。

## 上線前

1. 在 Supabase SQL Editor 執行 `supabase/migrations/059_bank_reconciliation.sql`。
2. 部署 ERP。
3. 使用「董事長」、「管理者」或「會計」角色登入。
4. 到「財務」點選「銀行對帳」。

此版本同時把 ERP session cookie 改為伺服器簽章格式，避免偽造財務角色。部署後既有使用者需要重新登入一次。正式環境建議設定獨立的 `SESSION_COOKIE_SECRET`；若未設定，系統會使用既有 `SUPABASE_SERVICE_ROLE_KEY` 作為簽章密鑰。

## 操作流程

1. 從企業網銀下載交易 CSV。
2. 在銀行對帳頁選擇 CSV，先檢查預覽內容。
3. 按「確認匯入」。系統會略過支出與已匯入過的相同交易。
4. 到「待確認」逐筆核對系統建議。
5. 確認金額、日期、匯款人、帳號末五碼與發票後，按「確認入帳」。
6. 系統寫入發票的「廠商付款日期」，再沿用 ERP 現有邏輯同步財務與分潤表。

## 匹配規則

- 銀行入帳金額必須等於同專案全部未入帳發票的含稅合計。
- 帳號末五碼、匯款日期、匯款人與收款申報可提高匹配分數。
- 系統最多顯示三個候選，但不會自行確認入帳。
- 多張發票的部分付款第一版不會自動建議，避免 ERP 過早把整個專案標為已入帳。

## CSV 相容性

解析器支援 UTF-8、Big5、民國／西元日期，以及常見的交易日期、存入金額、匯款人、帳號、摘要與交易序號欄位名稱。

首次使用時請先以少量交易測試。若國泰實際欄位無法辨識，提供一份移除帳號、姓名與金額等敏感內容的欄位範例，再調整欄位別名。
